\section{Tujuan}
\begin{enumerate}
    \item Mahasiswa memahami perbedaan antara Dockerfile (membangun image) dan Docker Compose (menjalankan container).
    \item Mahasiswa mampu menstranslasikan perintah CLI docker run yang panjang menjadi file konfigurasi 
docker-compose.yml 
    \item Mahasiswa mampu mengimplementasikan fitur Volumes untuk Hot-Reloading (perubahan kode langsung 
terlihat tanpa rebuild). 
\item Mahasiswa mampu mengelola environment variables menggunakan .env yang terintegrasi dengan Docker 
Compose.
\end{enumerate}
\section{Dasar Teori}
\subsection{Docker Compose}
Docker-Compose adalah alat untuk mendefinisikan dan menjalankan satu atau beberapa container yang saling terkait dengan sebuah command. Pada implementasinya kita dapat menggunakannya dengan membuat sebuah file berekstensi yaml/yml yang di dalamnya terdapat konfigurasi-konfigurasi terhadap service aplikasi yang akan dijalankan. Gambaran sederhananya seperti menyatukan semua Dockerfile dari setiap service aplikasi ke dalam sebuah file yaml (docker-compose file), dan selanjutnya dengan sebuah command, pengembang dapat membuat dan men-start semua service yang telah didefinisikan pada file yml tersebut. Script konfigurasi nya juga sangat mudah dan mirip dengan argumen-argumen saat kita ingin menjalankan sebuah Dockerfile. Kita bisa menggunakannya di semua lingkungan kerja: production, staging, development, dan testing \cite{key}.

\subsection{Orkestrasi Container}
Kontainer adalah komponen aplikasi ringan yang dapat di eksekusi yang menggabungkan kode sumber aplikasi dengan semua pustaka sistem operasi (OS) dan ketergantungan yang diperlukan untuk menjalankan kode di lingkungan apa pun. 

Kemampuan untuk membuat kontainer sudah ada sejak beberapa dekade yang lalu, tetapi baru tersedia secara luas pada tahun 2008 ketika Linux menyertakan fungsi kontainer di dalam kernelnya. Ini menjadi lebih penting setelah kedatangan platform containerisasi sumber terbuka Docker pada tahun 2013. (Docker sangat populer sehingga frasa "kontainer Docker" dan kata "kontainer" sering digunakan secara bergantian). Saat ini, kontainer kompatibel dengan banyak sistem operasi lain selain Linux, termasuk Windows \cite{ibmYangDimaksud}.

Berdasarkan gambar \ref{fig:tambah-phpmyadmin}, mahasiswa mendefinisikan sebuah \textit{service} bernama \texttt{phpmyadmin} yang berfungsi sebagai antarmuka grafis berbasis web untuk mengelola basis data MySQL secara mudah, tanpa harus menggunakan baris perintah atau terminal.

Secara lebih terperinci, konfigurasi tersebut diawali dengan penggunaan citra resmi versi terbaru dari Docker Hub yang dideklarasikan melalui sintaks \texttt{image: phpmyadmin:latest}. Kontainer ini kemudian diberi identitas khusus berupa nama \texttt{phpmyadmin\_jwt} melalui parameter \texttt{container\_name}. Agar layanan dapat diakses oleh pengguna dari luar kontainer, terdapat pengaturan \texttt{ports: - "8081:80"} yang berfungsi memetakan port internal kontainer (port 80) ke port komputer lokal mahasiswa (port 8081). Dengan demikian, mahasiswa dapat mengakses antarmuka phpMyAdmin secara langsung melalui peramban web dengan alamat \texttt{http://localhost:8081}. 

Selanjutnya, terdapat blok \texttt{environment} yang memuat variabel lingkungan esensial agar phpMyAdmin dapat terhubung dengan kontainer basis data. Melalui parameter \texttt{PMA\_HOST}, konfigurasi ini diarahkan untuk mengenali kontainer basis data yang bernama \texttt{database\_mysql} melalui jaringan internal pada port standar 3306 (\texttt{PMA\_PORT}). Sistem keamanan atau kata sandi utama juga diselaraskan menggunakan variabel \texttt{MYSQL\_ROOT\_PASSWORD}. Untuk memastikan kelancaran proses pemuatan sistem, direktif \texttt{depends\_on} digunakan guna menjamin bahwa kontainer \texttt{database\_mysql} akan dijalankan terlebih dahulu sebelum kontainer phpMyAdmin diaktifkan. Seluruh interaksi dan komunikasi antar-kontainer ini diwadahi di dalam sebuah jaringan virtual Docker yang sama, yang didefinisikan oleh mahasiswa pada bagian \texttt{networks} dengan nama \texttt{psait}.

\section{Kesimpulan}
Berdasarkan praktikum yang telah dilakukan, dapat disimpulkan bahwa penggunaan Docker Compose sangat mempermudah proses orkestrasi dan manajemen banyak kontainer secara bersamaan apabila dibandingkan dengan mengeksekusi perintah CLI secara manual. Mahasiswa telah berhasil menyusun dan mengonfigurasi berkas \texttt{docker-compose.yml} untuk mengintegrasikan layanan aplikasi pemrograman antarmuka (API), basis data MySQL, serta antarmuka phpMyAdmin ke dalam satu jaringan virtual yang saling terhubung. Selain itu, mahasiswa juga mampu mengimplementasikan fitur \textit{hot-reloading} dengan memanfaatkan \textit{volumes} sehingga perubahan pada kode sumber dapat langsung diamati tanpa perlu membangun ulang (\textit{rebuild}) citra kontainer, serta memahami penerapan manajemen variabel lingkungan menggunakan berkas \texttt{.env}.

Penerapan arsitektur tersebut terbukti berjalan dengan baik secara fungsional. Keberhasilan praktikum ini dibuktikan dengan berjalannya pengujian titik akhir (\textit{endpoint}) API secara lancar melalui aplikasi Postman. Selain itu, integrasi antarmuka phpMyAdmin juga beroperasi sesuai harapan, yang ditunjukkan melalui keberhasilan mahasiswa dalam melakukan berbagai operasi CRUD (Create, Read, Update, Delete) pada basis data secara langsung tanpa mengalami kendala.
