    \item Mahasiswa dapat melakukan autentikasi pada API

    \item Mahasiswa mampu melakukan login menggunakan token yang ada berdasarkan role yang tersedia

\section{Dasar Teori}
\subsection{API Authentication}
Autentikasi API adalah proses untuk memvalidasi identitas klien yang mencoba mengakses sumber daya server melalui API. Proses ini memastikan bahwa hanya pengguna atau sistem yang terotorisasi yang dapat berinteraksi dengan API, sehingga melindungi data sensitif dan fungsionalitas dari akses yang tidak sah \cite{echoapiAutentikasiMengapa}.

\section{Tugas dan Analisis}
Mahasiswa diberi 5 soal terkait dengan implementasi autentikasi API yang telah dilakukan. Berikut adalah soal-soal beserta hasil analisisnya:
\begin{enumerate}
    \item Apa yang terjadi ketika melakukan request akses data user menggunakan akun dengan 
role admin dan jwt token yang valid? \\
Jawab: \\ Ketika melakukan request akses data user menggunakan akun dengan role admin dan jwt token yang valid, maka request tersebut akan berhasil dan server akan mengembalikan data user yang diminta. Hal ini terjadi karena token yang valid menunjukkan bahwa pengguna telah terautentikasi dengan benar dan memiliki hak akses yang sesuai untuk mengakses data tersebut. hal tersebut dapat dilihat pada gambar \ref{fig:admin} yang menunjukkan bahwa request berhasil dan data user berhasil diakses menggunakan token yang valid.
    \item  Apa yang terjadi ketika melakukan request akses data user menggunakan akun dengan 
role admin dan jwt token yang tidak valid?\\
Jawab:\\
Ketika melakukan request akses data user menggunakan akun dengan role admin dan jwt token yang tidak valid, maka request tersebut akan gagal dan server akan mengembalikan response dengan status error. Hal ini terjadi karena token yang tidak valid menunjukkan bahwa pengguna tidak terautentikasi dengan benar atau token tersebut telah kedaluwarsa, sehingga server menolak akses ke data user. Response error yang diterima biasanya berupa pesan yang menyatakan bahwa token tidak valid atau akses ditolak, seperti pada gambar \ref{fig:unauth} yang menunjukkan bahwa request gagal karena token tidak valid.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{../images/unauth.png}
    \caption{Uji Mengakses Data dengan Token Tidak Valid}
    \label{fig:unauth}
\end{figure}

\item Apa yang terjadi jika akun dengan role user biasa (bukan admin) mengakses data user?
\\
Jawab:\\
Ketika akun dengan role user biasa (bukan admin) mencoba mengakses data user, maka request tersebut akan gagal dan server akan mengembalikan response dengan status error. Hal ini terjadi karena role user biasa tidak memiliki hak akses yang cukup untuk mengakses data user, sehingga server menolak akses tersebut. Response error yang diterima dapat dilihat pada gambar \ref{user}.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{../images/user.png}
    \caption{Uji Mengakses Data dengan Role User Biasa}
    \label{user}
\end{figure}
\item  Apa yang terjadi jika melakukan register dengan menginput role selain admin dan user 
biasa? \\
Jawab:\\
Jika melakukan register dengan menginput role selain admin dan user, maka proses registrasi akan tetap berhasil karena di dalam file register/index.php tidak terdapat validasi untuk membatasi jenis role yang diinputkan. Dapat dilihat pada gambar \ref{fig:mahasiswa}, bahwa role mahasiswa berhasil dibuat meskipun tidak sesuai dengan role yang telah ditentukan (admin dan user biasa).
\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{../images/mahasiswa.png}
    \caption{Uji Register dengan Role Mahasiswa}
    \label{fig:mahasiswa}
\end{figure}
\item Apa yang terjadi jika akun dengan role selain admin dan user biasa mengakses data user?\\
Jawab:\\
Jika akun dengan role selain admin dan user biasa mencoba mengakses data user, maka sistem yang dibuat tidak memiliki validasi untuk membatasi jenis role yang dapat mengakses data user. Oleh karena itu, sistem tersebut memiliki mekanisme authorization yang kurang baik.
\end{enumerate}

\section{Kesimpulan}
Berdasarkan hasil praktikum yang telah dilakukan, dapat disimpulkan bahwa implementasi autentikasi API menggunakan token JWT dapat memberikan keamanan yang lebih baik dalam mengakses sumber daya server. Dengan menggunakan token, hanya pengguna yang terautentikasi dengan benar dan memiliki hak akses yang sesuai yang dapat mengakses data atau fungsionalitas tertentu. Selain itu, penggunaan token juga memungkinkan untuk mengelola sesi pengguna dengan lebih efisien, karena token dapat memiliki masa berlaku tertentu dan dapat diperbarui sesuai kebutuhan. Namun, penting untuk memastikan bahwa implementasi autentikasi API dilakukan dengan benar dan aman, termasuk penggunaan algoritma enkripsi yang kuat untuk token dan validasi yang tepat untuk mencegah akses yang tidak sah.

Dengan adanya validasi role, sistem dapat membatasi akses ke sumber daya tertentu hanya untuk pengguna dengan hak akses yang sesuai, sehingga meningkatkan keamanan dan kontrol terhadap data yang sensitif. Namun, perlu diingat bahwa implementasi autentikasi API harus dilakukan dengan hati-hati dan mengikuti praktik terbaik untuk memastikan keamanan yang optimal.
