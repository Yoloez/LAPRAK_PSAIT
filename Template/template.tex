\section{Tujuan}
\begin{enumerate}
    \item Mahasiswa mampu memahami repplikasi database MySQL di Ubuntu Server.
    \item Mahasiswa mampu mengkonfigurasi master dan slave MySQL untuk replikasi database
    \item Mahasiswa mampu operasikan replikasi database MySQL untuk memastikan data konsistensi antara master dan slave.
\end{enumerate}

\section{Dasar Teori}
\subsection{Replikasi Database MySQL}
Replikasi database adalah sistem yang digunakan untuk menyalin, mendistribusikan data, serta melakukan sinkronisasi data antar database. Replikasi database juga dapat membantu meningkatkan kinerja database dengan mempercepat waktu akses dan meminimalkan waktu downtime yang mungkin terjadi jika hanya ada satu database tunggal.

Pada dasarnya sistem replikasi membutuhkan minimal dua buah server untuk digunakan sebagai master dan slave. Dengan menggunakan teknik replikasi, data dapat didistribusikan ke server yang berbeda melalui koneksi jaringan lokal maupun internet.

Selain itu ada yang menyebutkan bahwa Replikasi adalah proses menyalin dan memelihara objek database dalam beberapa database yang membentuk suatu sistem database terdistribusi. Replikasi database dapat meningkatkan kinerja dan melindungi ketersediaan aplikasi karena data pilihan alternatif akses (cadangan) ada \cite{rumahwebReplikasiDatabase}.

\section{Hasil dan Pembahasan}
\subsection{Hasil Praktikum}
Pada praktikum ini, mahasiswa melakukan konfigurasi replikasi database MySQL di Ubuntu Server. Proses ini melibatkan beberapa langkah, termasuk pengaturan master dan slave, serta memastikan data konsistensi antara keduanya. Berikut adalah langkah-langkah yang dilakukan:
\begin{enumerate}
    \item Mengecek versi MySQL di VPS Master \\
    Sebelum membuat MySQL slave, cek versi MySQL yang digunakan di VPS Master. Hal tersebut dikarenakan versi MySQL master dengan slave yang sama akan meminimalisir terjadinya error. Cek versi MySQL dapat dilakukan dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
sudo mysql --version
\end{lstlisting}
Setelah menjalankan perintah tersebut, akan muncul versi mysql di vps.
\begin{figure}[H]

    \includegraphics[width=0.9\textwidth]{../images/versi-mysql.png}
    \caption{Versi mysql master (8.0.45)}
    \label{versi-mysql}
\end{figure}

\item Download MySQL di komputer slave \\
MySQL server dapat diunduh pada link url berikut \url{https://dev.mysql.com/downloads/mysql/}

Halaman download dapat dilihat pada gambar \ref{community}. Pilih versi yang sesuai dengan yang ada di vps (versi 8.0.45).

\begin{figure}[H]
       \centering
\includegraphics[width=0.9\textwidth]{../images/versi-mysql-community.png}
    \caption{Donwload MySQL Community versi 8.0.45}
    \label{community}
\end{figure}
Pilih Windows (x86, 64-bit), ZIP Archive lalu klik download. Setelah berhasil mendownload file zip tersebut, extract all lalu tambahkan file my.ini di dalam folder ektrak tersebut. Isi dari konfigurasi file my.ini dapat dilihat pada gambar \ref{my.ini}

\begin{figure}[H]
       \centering
\includegraphics[width=0.9\textwidth]{../images/my-ini.png}
    \caption{Konfigurasi mysql }

Inisialisasi MySQL dengan perintah berikut. 
\begin{lstlisting}[language=bash, style=phphtml]
.\bin\mysqld --defaults-file=my.ini --initialize-insecure --console     
\end{lstlisting}
Perintah tersebut digunakan untuk membuat data yang terletak sesuai dengan apa yang telah didefinisikan di my.ini
\begin{figure}{H}
       \centering
\includegraphics[width=1\textwidth]{../images/eksekusi-myini.png}
    \caption{Inisiasi MySQL}
    \label{eksekusi-myini}
\end{figure}
Untuk menjalankan MySQL dapat dilakukan dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
\bin\mysqld --console 
\end{lstlisting}
Perintah tersebut digunakan untuk menjalankan MySQL server dan menjadikan terminal sebagai output log MySQL. 
\begin{figure}[H]
       \centering
       \includegraphics[width=0.9\textwidth]{../images/run-mysql.png}
    \caption{Menjalankan MySQL Server}
    \label{run-mysql}
\end{figure}

Setelah MySQL server berhasil dijalankan, buka terminal baru lalu masukkan perintah berikut. 
\begin{lstlisting}[language=bash, style=phphtml]
mysql -u root -P 3333      
\end{lstlisting}

Gunakan port 3333 seperti yang telah didefinisikan di my.ini. Jika sudah berhasil, tampilan mysql dapat dilihat pada gambar \ref{mysql}

\begin{figure}[H]

\item Mengatur konfigurasi MySQL di Master \\
Agar dapat melakukan replikasi database, maka perlu dilakukan beberapa konfigurasi di MySQL master. Konfigurasi tersebut dilakukan dengan mengubah bind-address menjadi 0.0.0.0 agar dapat diakses oleh pihak luar. Selain itu, perlu juga mengaktifkan server-id dan log-bin dengan cara uncomment (hapus komen \#). Setelah itu, restart MySQL server agar konfigurasi yang telah dibuat dapat diterapkan.

Untuk melakukan konfigurasi tersebut, dapat masuk ke file konfigurasi terlebih dahulu dengan perintah
\begin{lstlisting}[language=bash, style=phphtml]
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf
\end{lstlisting}

\begin{figure}[H]
       \centering
    \includegraphics[width=0.9\textwidth]{../images/konfigurasi-master-mysql.png}
    \caption{Mengaktifkan server-id dan log-bin di mysqld.cnf}
    \label{master-config}
\end{figure}

Setelah selesai mengedit file konfigurasi, tekan CTRL + S untuk menyimpan lalu tekan CTRL + X untuk keluar dari editor. Setelah itu, restart MySQL server dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
sudo systemctl restart mysql
\end{lstlisting}

\item Membuat MySQL user baru di Master (Ubuntu Server) \\
Sebelum membuat user baru di Master (Ubuntu Server), cek user yang telah dibuat sebelumnya terlebih dahulu. Masuk ke terminal MySQL Ubuntu server dan jalankan perintah seperti pada gambar berikut.
\begin{figure}[H]

    \includegraphics[width=0.9\textwidth]{../images/user-master.png}

Pada praktikum ini, mahasiswa akan membuat user baru dengan nama "replica\_user" dengan password "abc". Pembuatan user baru dapat dilakukan dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
CREATE USER 'replica_user'@'%' IDENTIFIED WItH mysql_native_password BY 'abc';
\end{lstlisting}

Berikan izin akses replication slave ke "replica\_user" dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
GRANT REPLICATION SLAVE ON *.* TO 'replica_user'@'%';
\end{lstlisting}

\begin{figure}[H]

\item Mengatur konfigurasi di MySQL slave bagian 2 \\
Buka kembali komputer yang digunakan untuk menjalankan MySQL slave, lalu masuk ke terminal MySQL. Jalankan perintah berikut untuk mengatur konfigurasi master di MySQL slave.
\begin{lstlisting}[language=bash, style=phphtml]
CHANGE MASTER TO MASTER_HOST='10.33.35.71',
MASTER_USER='replica_user', MASTER_PASSWORD='abc',
MASTER_LOG_FILE='mysql-bin.000001', MASTER_LOG_POS=1322;
\end{lstlisting}
Perintah tersebut digunakan untuk mengatur konfigurasi master di MySQL slave. Pastikan untuk mengganti MASTER\_HOST dengan IP address dari VPS Master, MASTER\_USER dengan nama user yang telah dibuat sebelumnya, MASTER\_PASSWORD dengan password yang telah dibuat sebelumnya, serta MASTER\_LOG\_FILE dan MASTER\_LOG\_POS dengan file dan posisi yang telah dicatat sebelumnya.

\subsection{Tugas dan Analisis}
Berdasarkan hasil praktikum yang telah dilakukan, pada database MySQL Master terdapat 6 database, sedangkan di database MySQL Slave hanya terdapat 5 database. Mengapa database sait\_db tidak tereplikasi ke MySQL Slave Bagaimana solusi yang harus dilakukan agar database sait\_db juga ter-copy ke MySQL Slave dan ikut tereplikasi ketika terdapat penambahan data.

\subsection{Hasil Analisis}
Berdasarkan analisis yang telah dilakukan, database sait\_db tidak tereplikasi ke MySQL Slave karena database tersebut dibuat sebelum konfigurasi replikasi dilakukan. 
Berikut merupakan langkah-langkah yang dapat dilakukan untuk mengatasi masalah tersebut:
\begin{enumerate}
    \item Ekspor Database di Master (VPS Ubuntu) \\
    Untuk mengekspor database sait\_db, dapat dilakukan dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
    sudo mysqldump -u root -p --databases sait_db > sait_db.sql
\end{lstlisting}
\item Download File dari VPS ke Windows (Master ke Slave) \\
Jalankan perintah scp (secure copy) untuk menyalin file sait\_db.sql dari VPS ke komputer Windows. Perintah scp dapat dilakukan seperti berikut:
\begin{lstlisting}[language=bash, style=phphtml]
# Format: scp [user_vps]@[ip_vps]:[lokasi_file_di_vps] [lokasi_tujuan_di_windows]
scp praktikan@10.33.35.71:~/sait_db.sql D:\mysql-8.0.45-winx64\mysql-8.0.45-winx64\Download\
\end{lstlisting}
\begin{figure}[H]
    \centering
    \includegraphics[width=1\textwidth]{../images/import-file-ke-slave.png}
    \caption{Mengekspor database sait\_db di MySQL master}
    \label{ekspor-database}
\end{figure}
\item Import Database di MySQL Slave \\
Setelah file sait\_db.sql berhasil disalin ke komputer Windows, langkah selanjutnya adalah membuat database sait\_db baru di MySQL slave. Kemudian, import file sait\_db.sql ke database sait\_db yang baru dibuat tersebut dengan perintah berikut:
\begin{lstlisting}[language=bash, style=phphtml]
    SOURCE D:/mysql-8.0.45-winx64/mysql-8.0.45-winx64/
    Download/sait_db.sql;
\end{lstlisting}
\begin{figure}[H]
    \centering
    \includegraphics[width=1\textwidth]{../images/success-import.png}
    \caption{Proses import database sait\_db di MySQL slave}
    \label{import-database}
\end{figure}
\item Cek Database di MySQL Slave \\
Setelah proses import selesai, cek kembali database yang ada di MySQL slave. Jika sudah terdapat 1 tabel (mahasiswa), artinya proses replikasi sudah berhasil dilakukan.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\textwidth]{../images/show-tables.png}
    \caption{Database sait\_db di MySQL slave setelah proses import selesai}
    \label{cek-database-saitdb}
\end{figure}

\end{enumerate}

\section{Kesimpulan}
Berdasarkan hasil praktikum yang telah dilakukan, dapat disimpulkan bahwa replikasi database MySQL di Ubuntu Server telah berhasil dilakukan. Proses replikasi melibatkan beberapa langkah, termasuk pengaturan master dan slave, serta memastikan data konsistensi antara keduanya. Selain itu, untuk mengatasi masalah database yang tidak tereplikasi, dapat dilakukan dengan mengekspor database di MySQL master, menyalin file ekspor ke komputer Windows, lalu mengimpor file tersebut ke MySQL slave. Dengan langkah-langkah tersebut, database yang sebelumnya tidak tereplikasi dapat berhasil di-copy ke MySQL slave dan ikut tereplikasi ketika terdapat penambahan data di MySQL master.
